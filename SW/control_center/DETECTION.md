# 실물 Detection · 파지 위치 접근

관제센터 Detection은 YOLO로 물체를 식별하고 MID-360으로 위치를 구한다. 물체와 일정 거리에서 멈추는 동작 대신, 책상 높이와 실제 가장자리·로봇 형상으로 파지할 차체 위치를 계획한다. Gazebo용 팔 이동 노드는 실행하지 않는다.

## 사용

1. Head D435·MID-360·차체 입력과 SLAM / 저장 지도 위치추정을 시작한다.
2. Detection에서 YOLO를 켜고 물체 이름을 **대상 적용**한다. 사과/green_apple/apple, 복숭아/peach, 토마토/tomato, 환타캔/fanta_can, 컵/cup, 바나나/banana를 지원한다.
3. 물체 박스에 대응하는 서로 다른 LiDAR 점 3개 이상, 위치 추정 3회의 12cm 이내 일치를 기다린다. 같은 종류의 물체가 여러 개면 처음에는 가까운 것을 선택하고 이후 25cm 안의 관측만 같은 대상으로 취급한다.
4. **책상 추가 이격**은 기본 0m다. 이는 물체 중심까지의 거리가 아니라 실제 로봇 형상과 책상 사이에 더 남길 거리다. 0이면 책상 높이에 걸리는 차체·랙·현재 팔 형상까지 최대한 접근하도록 계획한다. 저면 차체가 책상 아래로 들어갈 수 있는 공간과 책상 높이의 랙을 구분한다.
5. **접근 시작**을 누르면 Nav2를 자동으로 켜거나 활성화를 기다린다. 책상 준비 위치까지 Nav2 → 차체 정지 → 방향 정렬 → 책상 끝까지 저속 접근 → 물체 정면으로 최종 정렬 순서다. 이미 준비 영역에 들어와 있으면 Nav2로 뒤로 나가지 않고 정밀 접근으로 전환한다.
6. Detection과 NAV 양쪽에 같은 접근 단계가 표시된다. 지도에는 책상 윤곽, Nav2 준비 목표, 최종 파지 위치와 방향을 함께 표시한다. 접근 취소·NAV 이동 취소·검출 중지는 접근을 취소한다.

## Nav2 연결과 충돌 판정

`/navigate_to_pose` 엔드포인트 존재만으로 준비 완료라 하지 않는다. `bt_navigator`, `controller_server`, `planner_server`의 lifecycle이 모두 active이고 최근 응답인지 확인한 뒤 목표를 보낸다.

Detection 목표는 `navigate-to-detection.xml`에서 2Hz로 경로를 다시 계획하고 `GraspApproach` DWB 컨트롤러로 책상 준비 위치에 간다. 기존 `ObstacleFootprint`의 전체 3D 형상을 한 장의 XY 외곽으로 누르는 판정은 이 컨트롤러에서 제외한다. 높이가 다른 책상·차체·랙이 그 투영에서 겹쳐 모든 후보가 시작부터 거부되는 문제를 피하기 위한 것이다. `BaseObstacle`과 경로 평가를 유지하며, 실제 차체 명령은 모두 기존 3D 보호와 watchdog을 통과한다. 일반 NAV의 FollowPath 컨트롤러 설정은 유지한다.

Nav2가 준비 위치에 도달하지 못하면 관측된 다른 책상 면의 후보로 다시 계획한다. 책상 근처에서 무관한 90° 회전·후진 복구를 반복하지 않는다. 실패 시 DWB 충돌·진행 불가 등 수신한 원인을 함께 표시한다. inflation 반경에는 float32 외곽 전송 반올림을 위한 마이크로미터 단위 보정만 적용해 동일 수치의 반경 경고가 반복되는 것을 막는다.

## 책상 가장자리와 파지 위치

`head_lidar.py`는 물체 위치용 `/mid360/points_obstacles`와 책상 경계용 `/mid360/points_filtered`를 각 측정 시각에 `odom`으로 변환한다. 경계용 점군에는 바닥에 맞은 광선도 포함해, 상판 스캔이 단순히 가림으로 끊긴 곳과 실제 가장자리를 구분한다.

`grasp_approach.py`는 기존 `surface_geometry`의 수평 면·광선 경계 추정을 재사용한다. 물체 아래의 상판과 경계 관측 비율 0.4 이상인 면을 선택한다. 현재 팔 실측 관절을 적용한 공용 `RobotGeometry`의 OBB를 상판 높이 구간과 교차시켜, 그 구간에서 실제 로봇이 차지하는 범위로 최소 가장자리 거리를 계산한다. 상판 아래 차체의 전체 XY 외곽을 상판과 충돌한다고 간주하지 않는다. 계획용 상판 두께 구간은 윗면 아래 4cm이며, 실제 두께·다리·의자·팔과의 충돌은 현재 3D 관측과 전체 몸체 보호가 별도로 판단한다.

파지 위치에서는 물체가 정면에 오도록 yaw를 계산한다. 물체가 설정된 전방 도달 거리(기본 0.50m) 안에 있는 후보만 선택한다. Nav2 준비 거리는 책상 끝에서 차체 중심까지 기본 0.65m다. 이것은 마지막 정지 거리가 아니다. 최종 정밀 접근은 최대 0.06m/s, 0.25rad/s이며, 이동 전 0.035rad 이내로 방향을 맞춘다. 최종 위치 오차 8mm 이내, 물체 방향 오차 0.025rad 이내에서 0.6초 정지하면 접근 완료다. 이는 차체 도착 기준이며 팔 IK·파지 성공을 의미하지 않는다.

## 카메라에서 사라진 뒤

YOLO 촬영 시각의 optical 프레임에 LiDAR를 K/D로 투영한다. 대표 위치는 박스 중앙의 가까운 군집 안 실제 LiDAR 점이며 RGB-D 깊이로 바꾸지 않는다. 촬영 시각, LiDAR 시각, 물체 점·책상 경계·차체 목표를 `odom`에 저장한다. 이동을 시작하면 그 기준점을 고정한다. 물체가 카메라 시야에서 사라져도 현재 오도메트리로 남은 위치와 물체 방향을 계산해 계속 접근한다. SLAM 보정은 지도 표시와 Nav2 준비 목표 변환에만 반영한다.

새 접근은 30초 안에 확인한 물체 위치에서 시작하며, 시작한 접근은 최대 120초 동안 저장 위치를 사용한다. ROS 시각·오도메트리가 불연속이면 좌표를 버리고 다시 관측한다. 시야 밖에서 물체가 옮겨졌다면 저장 좌표 지우기로 다시 선택한다. 목표 기억과 현재 장애물 판단은 별개다. `/cmd_vel → 3D guard → actuator watchdog → Tracer` 경로와 몸체 기준 추가 충돌 여유 0cm를 유지한다. 정밀 접근 중 12초간 진행하지 못하면 중지하고 충돌 원인을 표시한다.

## 설정과 인터페이스

`config.json` / `config.example.json`의 detection 설정:

- `cloud_topic`, `surface_topic`, `camera_info_topic`: 물체·책상·원본 RGB 내부 보정 입력.
- `table_clearance`: 기본 추가 이격 0m, UI 설정 0~0.1m.
- `stage_edge_distance`: Nav2 준비 위치의 가장자리 거리, 기본 0.65m.
- `grasp_max_forward`: 물체 전방 도달 범위, 기본 0.50m. 실제 파지 가능성은 후속 실물 IK에서 판단한다.

`POST /api/detection`은 start/stop/select(label)/approach(edge_clearance)/cancel/clear를 지원한다. HTTP 202는 접수이며 실제 결과는 SSE detection_control에 표시한다. 이전 distance 필드를 보낸 화면에는 새로고침 안내를 반환한다.

`detection_control`과 `/detection/closed_approach/status`에는 Nav2 활성화·책상 계획·방향 정렬·정밀 접근 상태, 저장 목표와 촬영 시각, 책상과 파지 목표가 포함된다. `/detection/closed_approach/target`은 실제 촬영 시각과 odom 좌표를 보존한다.

관제센터와 Nav2를 재시작해야 새 코드와 GraspApproach 컨트롤러가 반영된다. 실행 중 지도는 먼저 pose graph로 저장하고 `--mapping --resume-mapping-params <profile.yaml>`로 이어 읽을 수 있다. 복원 프로필은 최초 SLAM 시작에만 사용하고, 이후 화면의 초기화는 기본 프로필로 새 지도를 시작한다. 이전 이동·접근 명령을 자동으로 재실행하지 않는다.
